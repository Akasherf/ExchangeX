## Critical data-safety rules

1. Do **not** run `docker compose down -v`, `docker volume prune`, `DROP DATABASE`, `TRUNCATE`, migration repair, or destructive failure tests against the live/existing ExchangeX Compose project or persistent volumes.
2. An isolated test must have an explicit, unique `COMPOSE_PROJECT_NAME`; check `docker compose config`, volume names, credentials and published port collisions before starting. Use disposable synthetic accounts/orders only.
3. Do not run `scripts/verify-writer-failover.sh` against a live API. It explicitly stops/restarts the API, and `CI=true` bypasses its interactive safety opt-in.
4. Preserve deployed data and secrets; never print database credentials or JWT secrets in evidence.
5. If any mandatory gate lacks evidence, leave v1.0.0 untagged and the release pending.

## Proposed release summary (pending verification)

ExchangeX is a Java 21 and Spring Boot exchange simulator featuring price-time-priority limit order matching, durable PostgreSQL command execution and recovery, exclusive writer fencing, authenticated REST interfaces, real-time WebSocket streams, React dashboard, Docker Compose, metrics and monitoring, and automated CI/restore verification.

This is **an exchange simulator and portfolio project**, not a real-money trading system. Throughput/latency figures, production readiness, and exactly-once recovery under fault injection must not be asserted without reproducible evidence.
